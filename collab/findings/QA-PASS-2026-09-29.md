# Full QA + usability pass — 2026-09-29

One QA pass over every mission, every weapon and every key, and one usability
pass over every stage, on branch `claude/peaceful-cannon-oqez4t` (PR #86).
Everything below is labelled the AGENT-RULES way: **FACT** is something a run
in this session printed; **ASSUMPTION** is my reading of it; **CANNOT VERIFY**
is what this environment cannot tell.

Environment caveat that applies to every number: GitHub runners and the cloud
container render through SwiftShader at 1–3 fps. Counts and state transitions
are trustworthy; timings and feel are not. Real-hardware confirmation of the
fixes below is still the missing step.

## 3. Keys — every key, real input, stage 0

`tools/qa-keys.js` presses 43 keys (Tab, Escape, F9, B, E…C, 1–0, `, comma,
period, Home, arrows) from a clean playing state and fails any key that leaves
the game paused / menu'd / dead, or leaves a menu painted over live play.

FACT (Gameplay QA on `6e57d33`): **PASS — 43 keys, none interrupted play.**

What it took to get there, all found by this sweep, all fixed and re-measured
with real input in CI:

- **Escape could not resume a paused game.** Two causes. game-manager's
  Escape handler dropped every trusted Escape while `document.fullscreenElement`
  was set (every desktop start requests fullscreen), so the resume branch was
  unreachable — traced by instrumenting the handler: ENTER, REACHED, return.
  And `pause-menu.js`, a second self-registering pause overlay, also bound
  bare Escape with an unguarded toggle. Fixed in `6a7ace0`: the fullscreen
  guard now covers the pause direction only; pause-menu's key binding removed.
  Before/after with the same probe: `paused, paused, paused, paused` →
  `playing, pointer locked, no overlay`.
- **K paused the game.** `weapon-attachments.js` bound bare K (game-manager
  binds it to the killstreak panel) and its `show()` drops pointer lock, which
  the lock-loss handler reads as "player opened a menu" → PAUSED + inventory
  painted over the attachments menu. Fixed in `6e57d33`: attachments on Alt+K,
  opened through the game's own pause so the lock-loss handler stays out;
  killstreak K ignores Alt; controls hint updated.
- Earlier in this branch, same class: R (reload vs radio radial → Alt+R),
  H/K (extras panel → Shift+H/K), Tab (double-bound + gated close path).

Still open: one page error per sweep, `Cannot convert undefined or null to
object`, with no JS frame in its stack (so no file to point at). Not tied to
any key; appears once per run.

## 5. Harness changes this pass (all in `tools/` and `.github/workflows/`)

- `qa-usability.js`: presses Enter on the briefing; separates full-screen
  effect layers; interval polling instead of rAF on a 1 fps renderer.
- `qa-weapons.js`: frame-budgeted waits; per-row pointer-lock check with
  re-acquire; rows without lock reported as not measured; exit-lock caller
  trace.
- `qa-keys.js`: Escape event-order trace; recovery that never clicks blind.
- `qa-play.js`: heartbeat while waiting for play (state, heap, frame counter,
  overlays) so a wedge leaves evidence.
- `full-qa.yml`: `only:` and `stages:` inputs; no concurrency group (a
  workflow-file push used to cancel live sweeps); weapons job long enough for
  125 rows.
